ข้อควรระวัง — Sequential Dialing Problem
ถ้าโทร 1,000 คน แต่ละสายใช้เวลา 30 วินาที = 8+ ชั่วโมง ในการรัน 1 campaign Parallel Dialing จึงจำเป็นมากสำหรับ scale ที่ใช้งานได้จริง

[Point Transaction]
  id, user_id, amount, type (credit/debit),

[Webhook]
  id, user_id, url, events[], secret, active

1.6 Analytics Metrics

1.9 Feature Gaps ของ BOTNOI

❌ Critical Gaps (Missing Core Features)
  • Parallel/Concurrent Dialing — เฉพาะ Sequential, scale ไม่ได้สำหรับ 10,000+ contacts
  • LLM-powered Conversation — Keyword matching ไม่รองรับ free-form response
  • Global Contact Book — ต้อง upload CSV ใหม่ทุก campaign
  • Real-time Analytics — ไม่มี live metrics ระหว่าง campaign running
  • Multi-user / Team Workspace — 1 account = 1 user
  • CRM/Webhook Integration — ผล call ไม่ไหลเข้า HubSpot/LINE OA
⚠️ Important Gaps (UX ด้อยกว่า World-class)
  • Visual Call Flow Builder — config ด้วย text/keyword เท่านั้น ไม่มี drag-drop
  • A/B Script Testing — ไม่รู้ว่า script ไหนดีกว่า
  • AMD (Answering Machine Detection) — ไม่แยก voicemail vs human
  • Sentiment Analysis — ไม่วิเคราะห์ความรู้สึกของผู้รับสาย
  • Smart Retry (AI-based) — retry ตามเวลาตายตัว ไม่ดู peak time ของ contact
  • Preview TTS Audio — ต้อง run campaign จริงถึงได้ยินเสียง

สรุป — สิ่งที่ควรนำมาปรับใช้กับ Ringo

✅ ต้องทำตาม (BOTNOI ทำถูก ควร copy)
  • Points prepaid system — Ringo มีโครงสร้างแล้ว แค่ต้อง implement transaction จริง (TASK-005)
  • Keyword-based Call Flow — Ringo มีแล้วใน Settings และทำได้ดีกว่า BOTNOI (มี 3 outcomes ชัดเจน + response message)
  • Script Template System — DB schema มีแล้ว แค่ขาด UI (TASK-009)
  • Export CSV + BOM — Ringo ทำดีกว่า BOTNOI อยู่แล้ว (รองรับ Excel ภาษาไทย) — รักษาไว้
⚡ ควรปรับปรุงก่อนทำตาม (ทำให้ดีกว่า BOTNOI)
  • Campaign Runner UX — Ringo มี animated progress, current-caller card, mini summary ที่ดีกว่า — รักษาไว้และ upgrade ด้วย Realtime (TASK-014)
  • Analytics — BOTNOI แค่ basic แต่ Ringo ควรทำ drill-down, date range filter, cross-campaign comparison ที่ลึกกว่า (TASK-004)
  • Contact Management — แทนที่จะทำ per-campaign contact แบบ BOTNOI ให้ทำ Global Contact Book เลย (TASK-013)
❌ ไม่ควรทำตาม (BOTNOI ทำผิด หรือ design decision ที่ไม่เหมาะ)
  • Sequential-only Dialing — Scale ไม่ได้ Ringo ควรออกแบบให้รองรับ parallel ตั้งแต่ต้น (TASK-017)
  • No Contact Book — บังคับ upload CSV ทุก campaign เป็น UX ที่แย่มาก อย่าทำตาม
  • Single-user Account — ถ้า Ringo target B2B ควร design org structure ไว้ใน data model แม้ UI จะยังไม่ทำก็ตาม
  • Keyword-only Intent Detection ระยะยาว — ใช้ได้ระยะสั้น แต่อนาคตต้อง move ไป LLM เพื่อรองรับ free-form conversation จริงๆ
